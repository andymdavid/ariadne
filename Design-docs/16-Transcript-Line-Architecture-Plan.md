# 16 - Transcript Line Architecture Plan

## Problem

Clip endings are still cutting off abruptly even after boundary validation and thought-aware refinement improvements.

The root issue is not missing timestamps. We already have word timestamps from local Whisper.

The real problem is architectural:

1. Raw Whisper `transcript_segments` are stored as the canonical transcript.
2. Those raw segments are acoustically convenient, not editorially correct.
3. Multiple downstream systems then rebuild better text structures independently:
   - clip candidate generation builds thought-like units in memory
   - caption generation builds cue lines and cue chunks from transcript lines
   - transcript realignment rebuilds word mappings per clip
4. The UI still renders the raw Whisper segments, so the user sees two-line blocks that often end mid-sentence.
5. Clip selection still inherits bad boundaries whenever fallback ranking/candidate logic touches the raw-segment model too directly.

So the current system has one low-quality canonical layer and several higher-quality derived layers that are rebuilt ad hoc.

That is the wrong architecture.

## Correct Architecture

### Canonical source of truth

The canonical transcript layer should be:

- `word timestamps`

Raw Whisper segments should become ingestion-only source data, not the main editing/boundary/display layer.

### Derived editorial layer

From word timestamps, derive stable transcript lines:

- each line has:
  - `id`
  - `episode_id`
  - `start_time`
  - `end_time`
  - `text`
  - `words`
  - `line_index`
  - optional `source_strategy`

These transcript lines should be the canonical editorial transcript used for:

- Clip Workspace transcript display
- transcript editing
- clip candidate generation
- clip boundary validation
- transcript-to-caption text basis
- export caption basis

### Presentation layer

From transcript lines, derive caption cues:

- one-line or multi-line cue chunks
- active-word highlighting
- preview/export cue timing

Caption cues should never be the storage layer. They are presentation only.

## Architecture Principles

1. One canonical editorial transcript model
   - no more raw Whisper segments in UI and separate thought units in clip generation

2. Word timestamps are authoritative for timing
   - all line boundaries derive from words

3. Transcript lines are authoritative for text
   - captions and clip boundaries should use the same line model

4. Cue chunks are ephemeral
   - generated from transcript lines for preview/export only

5. Editing should preserve structure coherently
   - line text edits update line text
   - line word timing is aligned from canonical word timings or regenerated by realignment

## Proposed Data Model

### Keep

- `transcript_segments`
  - keep as raw ingestion record from Whisper
  - rename conceptually in code to `raw transcript segments`

### Add

- `transcript_lines`
  - `id`
  - `episode_id`
  - `line_index`
  - `start_time`
  - `end_time`
  - `text`
  - `words_json`
  - `source_strategy`
  - `created_at`
  - `updated_at`

Optional later:

- `transcript_words`
  - only if we ever need fully normalized per-word querying in SQL
  - not needed for v1 if `words_json` is reliable

## Proposed Transcript Line Builder

Build transcript lines deterministically from word timestamps.

### Input

- ordered word list with `word`, `start`, `end`

### Break conditions

Prefer a new line when:

1. current line ends with terminal punctuation and the next word starts after a pause
2. current line ends with a complete thought
3. a strong pause occurs
4. line duration exceeds preferred max and the current text resolves cleanly
5. line word count exceeds preferred max and the current text resolves cleanly

Avoid breaking when:

1. line ends with conjunction/preposition/article/auxiliary
2. next word clearly continues the same thought
3. the current line is still syntactically incomplete

### Output goals

- lines should read naturally in the Transcript panel
- lines should be reasonable candidate start/end anchors
- lines should not routinely end on fragments like:
  - `everyone will`
  - `you can`
  - `because`
  - `the`

## Required Pipeline Changes

### 1. Ingestion

After Whisper transcription completes:

1. store raw `transcript_segments`
2. flatten words
3. build `transcript_lines`
4. persist `transcript_lines`

### 2. Clip generation

`clip_generation` should use `transcript_lines`, not raw segments or ad hoc normalization.

That means:

- remove `normalizeTranscriptIntoThoughtUnits(...)` as a primary long-term boundary basis
- replace it with `buildTranscriptLinesFromWords(...)` or equivalent stored-line loader

### 3. Clip ranking fallback

Recovered/non-JSON/fallback ranking paths must only select from candidates based on `transcript_lines`.

### 4. Transcript UI

Clip Workspace and Clip Editor should render `transcript_lines`, not raw Whisper segments.

This solves the visible two-line-block issue.

### 5. Transcript editing

Editing should update `transcript_lines`.

If line edits materially change wording:

- align edited text to existing line words where possible
- otherwise realign from audio for that clip window

Raw Whisper segments should not be the thing the user edits anymore.

### 6. Captions

Caption line input should come from `transcript_lines`.

Then `buildCaptionCues(...)` can continue to derive cue chunks for preview/export.

## Required API Changes

### Replace or de-emphasize

- `getTranscriptSegments`
- `getClipTranscriptSegments`
- `updateTranscriptSegment`

### Add

- `getTranscriptLines(episodeId)`
- `getClipTranscriptLines(clipId)`
- `updateTranscriptLine(episodeId, lineIndex or lineId, text, words?)`
- `rebuildTranscriptLines(episodeId)`
- `realignClipTranscriptLines(clipId)`

## Migration Strategy

### Phase 1

Add `transcript_lines` without removing `transcript_segments`.

On new pipeline runs:

- build and persist both

On existing episodes:

- lazy-build `transcript_lines` from existing segment words on first open or via migration tool

### Phase 2

Switch UI reads to `transcript_lines`.

### Phase 3

Switch clip generation/candidate generation to `transcript_lines`.

### Phase 4

Switch transcript editing to line-level only.

### Phase 5

Remove codepaths that treat raw segments as the main editorial transcript.

## Why this is the correct design

Because it separates concerns cleanly:

- raw transcription data = ingestion artifact
- transcript lines = editorial/source-of-truth text layer
- caption cues = rendering layer

Right now those concerns are blurred, and the system keeps inheriting bad segment boundaries into clip selection and transcript display.

## Execution Todos

### Slice 1: Data model

- add `transcript_lines` table
- add database CRUD for transcript lines
- add shared types for transcript lines

### Slice 2: Line builder

- implement deterministic `word -> transcript lines` builder
- add tests/fixtures for:
  - terminal punctuation
  - pause-based splits
  - dangling phrase prevention
  - lowercase Whisper transcript cases

### Slice 3: Pipeline integration

- build/store transcript lines after transcription
- keep raw segments for provenance

### Slice 4: Clip generation integration

- switch candidate generation to stored transcript lines
- remove dependence on ad hoc transcript normalization for primary fallback

### Slice 5: UI integration

- switch Clip Workspace / Clip Editor transcript rendering to transcript lines
- remove visible raw Whisper block structure from the editor

### Slice 6: Editing integration

- update transcript editing to mutate transcript lines
- update realignment service to operate on transcript lines

### Slice 7: Caption integration

- make preview/export consume transcript lines directly for cue generation

## Acceptance Criteria

1. Transcript panel no longer shows arbitrary raw Whisper two-line blocks.
2. Clips no longer routinely end on fragments like `you can` or `everyone will`.
3. Transcript, Clip Preview captions, and Export captions all derive from the same line model.
4. Editing transcript text in Clip Workspace updates the same canonical line model used by preview/export.
5. Raw Whisper segments remain available for provenance/debugging, but are not the visible editorial transcript layer.
